# Многопользовательская QCL — зафиксировано на будущее

## Идея

QCL не обязана оставаться платформой одного автора. Метод (Сюжет → Скрипт → Истинный отклик / отклик по мудрости Аллаха) применим к жизни любого человека. В перспективе — система, куда любой пользователь может зайти под своей учётной записью и вести свою собственную документацию сюжетов, с возможностью маркировать каждую запись как **приватную** или **публичную**.

## Почему это НЕ следующий шаг сейчас

Текущая связка Obsidian → Quartz → git push → GitHub Pages — статический сайт одного автора. Она достаточна и правильна для текущей задачи: наработать дисциплину, накопить практику на реальных записях, проверить, работает ли сама структура шаблона на живом материале.

Многопользовательская версия требует принципиально другой архитектуры:
- бэкенд с аутентификацией пользователей
- база данных вместо файлов в git (записи с полем private/public, привязанные к user_id)
- права доступа на уровне отдельной записи, а не всего репозитория
- отдельный рендеринг: публичная лента показывает только public-записи разных людей, личный кабинет — всё своё

Это уже не Quartz-сайт, а полноценное веб-приложение — Quartz в этом сценарии в лучшем случае остаётся способом рендерить markdown внутри страницы.

## Решение

Открытый вопрос архитектуры отложен. Приоритет — довести до практики личный vault: набрать 5-10+ полноценных записей, проверить шаблон и методологию сверки с Писаниями на реальном материале, и только после этого возвращаться к вопросу масштабирования на много пользователей.

Когда дойдёт время — стоит рассмотреть отдельно от Quartz: фреймворк с бэкендом и БД (записи из markdown можно мигрировать), либо надстройку над существующими git-based решениями (например, приватные форки на пользователя — но это не масштабируется и, скорее всего, будет отвергнуто в пользу нормальной БД).
